# 夜间多 Agent 交流与结算

## 一次夜间结算的信息流

1. `EndDayService` 锁定本日状态并调用 `NightSimulationService`。
2. 夜间服务读取剧本包中的 `night_agent_scenes`，只选择日期和旗标条件匹配的场景。
3. 对自主场景，候选池中的每名 NPC 先独立决定今晚联系 0 到 n 名对象。服务端校验对象必须来自剧本候选池，并限制最大联系人数。
4. 每次联系先作为邀请；受邀 NPC 独立选择接受、拒绝或延后。只有接受者进入交流小组。
5. 每个被接受的联系结果形成实际交流小组；相同或被更大群组包含的成员组合去重。没有邀请被接受时，本场景当晚不发生对话。
6. 服务端为实际参与的每名 NPC 单独构造上下文：
   - 人物设定与结构化大五人格；
   - 该 NPC 的私有处境；
   - 场景目标；
   - 已经发生的对话；
   - 当前 NPC 可选的剧本动作；
   - 该 NPC 配置的模型 ID。
7. 同一小组中的 NPC 按轮次交替调用模型。模型只能返回当前 NPC 的对白，不能替他人发言。
8. 所有对白结束后，再分别调用每名 NPC，让其基于完整交流记录选择一个结构化动作。
9. 服务端校验动作 ID、执行者、目标、日期/旗标条件。非法提案被记录为拒绝，不进入结算。
10. 服务端按动作的 `resolution` 结算：
   - `consensus`：所有参与者都选中同一动作才执行；
   - `unilateral`：任一有权执行者选中即可执行。
11. 只有剧本动作中预先登记的 `effects` 和 `npc_deltas` 可以写入状态。
12. 当夜实际参与者再判断是否向次日玩家发起强制群组会谈：
    - `crowd` 标签只能发起群众上访；
    - `cadre` 标签只能发起干部会谈；
    - 可以明确选择不发起；
    - 同组 NPC 仍需接受邀请，至少两名 NPC 接受才建立群组会谈。
13. 群众上访排在干部会谈之前，同类型按紧急度排序。次日必须依次完成队列，才恢复普通行动。
14. 夜间记录整体写入 `session.night_logs`。同一故事日再次调用时直接返回原记录，不重复调用模型或结算。

## 保存的信息

内部存档保存：

- 场景 ID、参与 NPC；
- 每名候选 NPC 联系了谁、选择零人的决定及其理由；
- 每名受邀 NPC 的接受、拒绝或延后结果及理由；
- 每轮发言人、原始对白、轮次和模型 ID；
- 每个 NPC 的动作提案、目标和理由；
- 提案是否通过白名单校验；
- 最终执行的动作 ID。
- 是否发起次日群众上访或干部会谈、参与者、议题、诉求、紧急度与同伴响应。

强制群组会谈另保存当前队列、活动会谈和已完成会谈。玩家每轮回应后，各参与 NPC 使用隔离上下文分别发言；首版最多三轮，完成后自动归档并激活下一项。

玩家复盘接口会移除 `agent_exchanges`，只返回公开夜间叙事和晨间结果。研究或调试端可以从受控的会话存档读取完整交流。

次日晨间卡会根据当夜实际成立的交流生成有限视角摘要。摘要只描述交流方向，例如试探、协调口径、相互防备或调整材料保管方式；不显示参与者姓名、原始台词、具体证据位置或秘密计划。若交流成立但没有行动，使用场景级概括；若执行了登记行动，使用行动级概括。该摘要由规则配置确定，不再次调用 LLM。

终端登录后、选择 session 前会询问是否观看 NPC 夜间对话。开启后，客户端通过本人 session 的 `/night-dialogues` 接口展示联系人选择、邀请响应、逐轮转录、模型 ID、行动提案、次日会谈发起决定和最终执行结果；还可以从游戏菜单再次打开。

## D29 首个场景

`night_d29_qian_zhao_private_room` 的候选池包括钱伟、赵建国、孙强和刘三。每人最多主动联系两人；实际小组进行两轮交替发言。当前动作池：

- `night_unify_story`：双方共识；增加腐败证据风险，形成攻守同盟；
- `night_move_originals`：赵建国单方且调查已启动时可选；降低现存证据并造成原件缺失；
- `night_cut_off_counterpart`：双方已撕破脸时可单方选择；形成钱赵生隙；
- `night_hold_position`：不产生硬状态变化。

旧 D29 中对应的三条固定条件结算已经移除；“砸钱普涨”造成的群众攀比仍是固定社会后果，尚未迁入 Agent 场景。

## 多模型配置

场景的 `model_ids` 可以按 NPC 指定模型。未指定时使用全局 `ROLE_LLM_MODEL`。因此当前既支持“同一基础模型、不同隔离 Agent”，也支持在同一 OpenAI-compatible 服务端为不同 NPC 选择不同模型。

模型永远只是提案者。更换模型不会扩大其状态写入权限。
