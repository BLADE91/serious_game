## 1. 设计判断

### 1.1 已核实的现状

1. 当前规则表确实列出31项行动，但其中大量行动只有行动点成本、参数记录和叙事文本，没有稳定的资源扣减、事实产出、指标变化或后续结算。[已验证：`code/backend/content/packages/pkg_gameplay_v2/action_rules.json:1`、`code/backend/content/packages/pkg_gameplay_v2/resource_actions.json:1-12`]
2. 当前正式规格已经规定：玩家主动行动原则上不能直接增加签约户数；行动只能铺路，签约必须在NPC承诺、正式审批、交付等明确剧情结算点发生。“攻坚宗族族长”是现有明确例外链条之一。[已验证：`开发交接补充/30_动作与行动点效果规格.md:9-16`、`开发交接补充/30_动作与行动点效果规格.md:146-153`]
3. 当前项目拥有36户、122名安置人口、4745㎡合法住宅、5950㎡认定宅基地、82.8亩承包地、4.5亩其他土地的逐户底账。[已验证：`code/backend/content/packages/pkg_gameplay_v2/households.json:1-61`]
4. 总预算为8000万元，其中200万元已发生或处于历史挂账状态，当前可支配量按7800万元设计；行动点基础值为每日8点。[已验证：`code/backend/content/packages/pkg_gameplay_v2/numbers.json:4-15`、`code/backend/docs/01_玩法与行动/01_补偿政策待确认数字.md:49-54`]
5. 补偿单价、过渡费、奖励、安置房、坟墓迁移、医疗与就业等关键政策输入目前仍缺正式值。[已验证：`code/backend/docs/01_玩法与行动/01_补偿政策待确认数字.md:9-26`]

### 1.2 核心问题

- “上门走访”和“谈心谈话”在玩法上只是强度不同，不应占两个同级入口。
- “群众工作转介”“党员示范”“宗族族长”本质上都是借助关键人物影响群体，应成为同一行动的不同渠道。
- “提高住房条件”“就业创业”“差异化补偿”本质上都是个案方案组件，不应被当作三个彼此孤立的按钮。
- “查看村账”“查阅县档案”都是档案审计，只是资料源、授权要求和证据强度不同。
- “第三方水质检测”“查阅儿童血铅报告”都是环境健康取证，只是成本、时效和证据等级不同。
- “见县委书记”“与市里沟通”“联络张莉”都是正式协调，应通过目标、诉求和报送材料区分。
- “孤立闹事者”不是合格的治理行动名称，也缺乏程序边界；应改造成冲突降级与现场秩序处置。
- “成立搬迁专班”不应每天重复成立；“请郑向东汇总线索”也不应反复消耗行动点。

### 1.3 重构原则

1. 一个按钮代表一种稳定的决策逻辑，而不是一句不同的文案。
2. 相近行为用“行动模式”表达；模式可以拥有不同成本、前置条件和效果。
3. 每次行动必须至少产出一种可追踪结果：关系变化、事实、证据等级、程序里程碑、资源预占、指标变化或风险。
4. 玩家执行前看得到成本、缺失条件和可能风险；执行后看得到为什么得到该结果。
5. 主动行动不直接制造签约户数；签约只在明确的NPC承诺或正式交付结算点发生。
6. 不用纯随机数掩盖设计空白。结果由准备、关系、证据、对象匹配、疲劳和对抗压力计算。

### 2.1 “行动造成什么”的正确含义

一个行动不能再被理解为“点击后播放一段文字并修改几个数值”。它应当创建一个具体事件，事件中有真实参与者、有限信息、可追问对话、形成的文件或承诺，以及事件结束后的社会传播。

每个行动的完整结果包含五层：

1. **现场结果**：谁来了、谁拒绝、说了什么、暴露了什么矛盾。
2. **业务产物**：会议纪要、政策版本、报价单、证词、样本、案号、审批意见或法律文书。
3. **人物结果**：每个NPC分别接受、观望、反对、警惕、结盟或退出，而不是所有人统一加减信任。
4. **资源结果**：行动点、人员时间、车辆、名额、房源、预算预占与正式支付。
5. **世界结果**：当晚的信息传播、群体联合、干部反制、媒体报道、后续NPC解锁和剧情结算。

### 2.2 LLM与权威规则的边界

当前白天会谈只具备单NPC角色回合能力，角色模型只能在允许事实范围内说话，也不能直接提交旗标。[已验证：`code/backend/src/serious_game_backend/application/npc_turn_service.py:12-93`]

当前夜间系统已经具备多NPC参与、分轮对话、每名NPC分别提出行动，以及规则层按白名单和“单方/共识”条件执行效果的雏形。[已验证：`code/backend/src/serious_game_backend/application/night_simulation_service.py:119-265`、`code/backend/content/packages/pkg_gameplay_v2/social_rules.json:102-160`]

因此建议把夜间多Agent编排抽成通用的“场景编排器”，同时服务白天和夜间。职责必须严格区分：

| 组件 | 负责 | 不负责 |
|---|---|---|
| NPC角色LLM | 依据角色设定、已知事实、私人利益和现场记录发言；提出受限行动 | 修改预算、签约户数、证据等级、政策权限和剧情旗标 |
| 主持/流程控制器 | 控制发言顺序、轮次、追问、超时、议题和结束条件 | 代替NPC表达立场 |
| 记录员LLM | 从真实转录中抽取诉求、承诺、争议、待核事实和行动项 | 发明没说过的事实，判断承诺是否有法律效力 |
| 计算与规则层 | 校验权限、证据、资源、程序；产生确定性状态变化 | 自由生成角色对白 |
| 夜间传播器 | 依据关系边、共同议题和白天记录生成联合行动场景 | 无条件让所有NPC知道全部信息 |

| A08 约谈干部 | 围绕一项具体事实进行个别谈话、出示材料并要求解释 | 调用1个目标干部LLM；玩家分阶段选择询问、出示证据、质证；LLM只能在其知识边界内回答 | 谈话记录、已承认事项、矛盾点、可核线索、是否拒绝签字 | 对证充分可获得口供或材料位置；无证据施压会促使其串联、转移材料或向上投诉 |
| A09 启动核查与问责 | 先审查线索是否达到立案标准，再封存材料、指定人员并启动调查 | 立案判断不用角色LLM；调查中分别调用涉事人、证人NPC；可用审查LLM整理证据矩阵，但不能定罪 | 核查案号、调查范围、证据清单、封存状态、回避人员、期限 | 封存及时可阻止毁证；程序错误会让证据失效；查实/查否都必须形成可说明结论 |
| A10 正式协调 | 向张立、县委或市级部门报送事实、已做工作和明确请求，并获得答复 | 调用1个目标官员LLM进行问答；其只能在预设权限表内提出批准、补正、转办或拒绝 | 批示、补正清单、责任部门、额度、期限或书面拒绝 | 材料扎实获得资源与政治支持；空泛请示被退回；越级绕开本级会损失政治资本 |
| A11 审计账档 | 带着明确审计问题调取村账、凭证、县档或历史卷宗，复制或封存 | 找到什么由档案索引和旗标决定，不由LLM编造；保管人NPC LLM处理授权、询问和阻挠；抽取LLM可整理原件内容 | 调阅清单、原件/复制件状态、差异表、保管链和下一条审计线索 | 封存成功形成可用证据；只看未留存只能形成线索；惊动对象且未封存可能引发夜间转移原件 |
| A12 环境与健康取证 | 取得同意、确定采样点与时间、封样送检，或依法调取脱敏病历 | 家庭/工作人员NPC LLM负责同意和说明；检测值、病历值和因果等级必须由内容数据和规则层生成 | 同意书、采样记录、样本状态、报告到期日、病历清单、隐私级别 | 链条完整可获得E3报告；时间错误可能只能证明冲洗；泄露儿童信息会造成家庭反对和媒体危机 |
| A13 保护性证人访谈 | 安排安全地点，说明保密范围，取得证词并拆出可验证细节 | 调用1个证人NPC LLM；记录员抽取时间、地点、人物和材料；证人可随压力主动终止 | 证词原文、可验证命题、保护等级、回访时间、身份知悉范围 | 保护可靠可继续提供线索；泄密会撤证、失联或遭反制，并在夜间改变其他知情人的意愿 |
| A14 媒体沟通 | 背景通报、记者提问或陪同调查，明确哪些材料公开和如何脱敏 | 调用王芳、陈默等已解锁记者NPC LLM；若多名记者在场则使用多Agent问答；规则层限制可公开事实 | 问答转录、已公开材料、待答问题、记者报道意向和发布时间 | 透明一致能降低谣言；口径冲突会成为报道重点；压稿或喂假材料可能促成记者结盟调查 |
| A15 现场调查 | 按路线进入村庄、厂区、河道或安置点，观察、拍照并接触现场人物 | 场景控制器先确定真实观察；现场出现的1~3个NPC分别调用角色LLM；不能因玩家一句话生成不存在的物证 | 观察记录、照片位置、在场名单、待采样/待访谈机会和现场风险 | 问题明确可解锁新行动机会；走马观花只得到环境描述；被提前通风会看到布置过的现场 |
| A16 交叉印证 | 将两个独立来源围绕同一命题并列，检查一致、矛盾和来源依赖 | 不需要角色LLM；可用抽取LLM做语义对齐，但独立性和证据升级由规则判定 | 命题卡、来源图、一致点、矛盾点、证据新等级或最小补证建议 | 一致则升级证据；矛盾不会“平均掉”，而是产生追查任务；同源转述不能升级 |
| A17 推进法定程序 | 法务依清单检查告知、评估、听证、救济和证据，提交审查或申请文书 | 法务NPC LLM可解释缺口和风险；法院/审批结论不能由自由LLM随意决定，必须是规则或剧本白名单结果 | 程序检查表、缺件、送达记录、申请、受理/退回/生效文书 | 完整则推进一个里程碑；跳步被退回并放大不稳定；任何成功都不等于立即清场 |
| A18 冲突降级与现场秩序处置 | 识别冲突等级，先沟通、分流、警告，只有达到条件才进入现场管控或执行 | 调用当事NPC、调解人/指挥人员的多Agent场景；每轮后规则层重算风险，玩家决定维持、降级或升级 | 风险评估、警告记录、当事人诉求、现场命令、伤情和影像记录 | 调解成功可恢复谈判；不当升级造成受伤、信任崩塌和媒体调查；合法强制也有固定社会代价 |

### 2.4 公开听证的完整实现示例

公开听证应该是一个真正的多人互动场景，而不是“扣3点后信任+4”。

#### 2.4.1 会前准备

玩家选择：

- 听证主题：统一补偿、安置房、坟墓/祠堂、环境健康或程序争议；
- 政府席：主持人、政策解释人、财政/法务责任人；
- 村民席：从已解锁且与议题相关的NPC中邀请3~6人；
- 旁听与媒体：是否允许王芳、陈默等已解锁媒体参加；
- 公开材料：政策版本、逐户信息只能展示脱敏汇总，证据材料按公开等级控制。

系统先发送通知。NPC依据关系、议题、时间冲突和对政府的预期决定到场、委托代表或拒绝。拒绝也是结果，不能强制所有角色到齐。

#### 2.4.2 多Agent回合

| 回合 | 谁发言 | 模型任务 | 规则限制 |
|---|---|---|---|
| 1. 开场陈述 | 每名受邀NPC | 陈述本人与所代表群体的核心诉求 | 只能使用个人已知事实 |
| 2. 政策说明 | 政府责任NPC | 解释已批准政策和未决事项 | 未批准内容不得说成承诺 |
| 3. 质询 | 村民NPC依次提问 | 根据前文追问矛盾、比较相似户 | 每人最多1个主问题和1次追问 |
| 4. 回应 | 玩家或责任NPC | 回答、承认未知、承诺核验或拒绝 | 每项承诺校验权限与期限 |
| 5. 相互回应 | 立场冲突的NPC | 支持、质疑或补充他人陈述 | 只允许回应转录中已经出现的内容 |
| 6. 收束 | 每名NPC | 表达接受、保留、反对或退出 | 不能直接决定签约户数 |

每名NPC应使用独立角色上下文和私人信息。不能把六个人拼进一个提示词，让单个模型同时扮演所有人，否则角色知识会互相泄漏，立场也容易被模型统一化。

#### 2.4.3 记录员与结算

记录员LLM只能根据转录输出结构化草案：

```text
claims[]             各方主张
questions_answered[] 已明确回答的问题
questions_open[]     待核问题
commitments[]        政府现场承诺
disagreements[]      仍存在的分歧
follow_up_actions[]  后续责任人与期限
```

随后规则层逐项校验：

- 承诺人是否有权限；
- 承诺是否有预算或资源；
- 回答是否与当前政策版本一致；
- 是否出现同类户不同口径；
- 未决问题是否给出责任人与期限；
- 是否泄露隐私或调查材料。

听证不使用一个笼统的“成功/失败”按钮，而是分别结算：

| 实际结果 | 直接后果 | 夜间后果 |
|---|---|---|
| 主要问题有依据地答复，未决问题都有期限 | 到场NPC程序认可上升；生成可引用纪要 | 观望NPC经关系网络获知，部分人愿意进入A01/A05 |
| 政策本身不受欢迎，但解释一致、程序完整 | 不提高方案接受度，但降低谣言和敌意 | 反对者可能组织合法联名，而不是突然“被说服” |
| 同类户口径矛盾 | 相关NPC信任下降，生成“横向比较争议” | 相似户互相核对，形成联合质疑 |
| 现场越权许诺 | 短期气氛可能改善，但承诺进入高风险待兑现表 | 到期无法兑现时触发双倍信任损失和媒体风险 |
| 回避健康、账目等已有事实 | 记者与知情NPC捕捉回避点 | 可能形成媒体—村民联合调查 |
| 现场失控或侮辱参与者 | 听证中止，程序里程碑不成立 | 反对联盟扩大，部分NPC暂时拒绝单独会谈 |

这使公开听证的价值来自“把私人矛盾变成可记录、可回答、可追责的公共问题”，而不是神奇地让所有人提高信任。

## 4. 两项移出重复行动栏的功能

### S01 成立搬迁专班：一次性组织决策

发生时机：玩家接手任务、完成首次情况汇总后，只能选择一次；基础成本3点。

| 方案 | 初始配置 | 常驻优势 | 常驻代价 |
|---|---|---|---|
| 群众工作型 | 2名走访员、1名政策员、1名记录员 | A01、A02首次执行准备度+1；每天可多维护1段NPC关系 | 审计和法律行动首次成本+1 |
| 证据法治型 | 1名审计员、1名法务、1名调查员、1名记录员 | A09、A11、A12、A17准备度+1 | 初期群众工作关系收益-1 |
| 均衡型 | 1名走访员、1名政策员、1名调查员、1名法务 | 无短板，第一次跨类别组合行动额外+1准备度 | 没有单项专长 |

专班允许后续通过A07班子会调整一次，但需产生干部不满+3并占用当天一个部门资源槽。这样“组织能力”成为长期选择，而不是每天点一次的空按钮。

### D01 郑向东线索汇总：免费案头功能

- 每个时段可免费使用一次，不消耗行动点，不推进时间。
- 只整理玩家已经获得的线索，输出“人物—事件—证据—待验证项”四栏。
- 不创造新事实，不提高证据等级，也不能替代A16交叉印证。
- 若玩家没有新增线索，界面直接提示“暂无可汇总的新材料”，不制造假进展。

## 5. 核心实现路径：统一结算框架

### 5.1 六阶段生命周期

| 阶段 | 系统行为 | 玩家必须看见的内容 |
|---|---|---|
| 1. 预检 | 检查前置事实、对象状态、人员、物资、权限、冷却与行动点 | 缺什么、去哪里补、此时执行的风险 |
| 2. 承诺 | 扣除行动点；对房源、名额或预算做“预占”而非立即支付 | 实扣行动点、预占资源、预计完成时间 |
| 3. 执行 | 根据模式调用对应场景、对象和资源 | 采取了什么步骤，不只是一段泛化叙事 |
| 4. 即时结果 | 写入关系、线索、事实、程序、指标或资源变化 | 每项变化的原因与数值 |
| 5. 延迟响应 | 日终或夜间让NPC、媒体、干部和利益群体响应 | 谁因为什么作出反应 |
| 6. 剧情结算 | 在承诺、审批、签字、交付、司法文书等节点兑现预算和签约 | 是否发生支付/签约、对应依据、是否已锁定防重 |

### 5.2 结果等级

行动一旦通过预检并开始执行，就扣完整行动点；“没有查到东西”也是成本。预检失败则不扣点。

结果分数采用可解释公式：

`结果分 = 准备度(0~3) + 关系(−2~2) + 证据(0~3) + 对象匹配(0~2) − 疲劳惩罚(0~2) − 对抗压力(0~3)`

| 分数 | 等级 | 通用结算 |
|---|---|---|
| ≤1 | 反效果 | 没有目标产出，并触发一项与失败原因相关的风险 |
| 2~3 | 无效 | 消耗行动点，只记录接触、未完成或无结果状态 |
| 4~5 | 部分成功 | 获得线索、关系或程序进展，但仍需补一个条件 |
| 6~7 | 标准成功 | 获得该模式规定的完整即时产出 |
| ≥8 | 突破 | 标准产出外，额外解锁一个NPC、事实或资源机会 |

结果面板必须逐项显示评分来源。若希望保留少量不确定性，可只在同分档内使用固定种子的叙事差异，不能让随机数跨越结果等级。

### 5.3 允许写入的效果类型

- `relationship_delta`：某NPC对玩家或政策的关系变化。
- `metric_delta`：信任、稳定、政治资本、媒体风险、廉政、干部不满、疲劳。
- `fact_unlock`：获得事实；事实仍需标注来源与证据等级。
- `evidence_upgrade`：传闻→单源线索→已印证事实→可用于程序的证据。
- `procedure_milestone`：听证、审计封存、法律审查、审批、文书送达等。
- `resource_reserve/release/spend`：预占、释放或正式消耗预算/房源/名额。
- `npc_unlock/lock`：NPC进入可互动、暂时拒绝、失联或受保护状态。
- `scheduled_effect`：明确在日终、夜间或若干日后触发的效果。
- `household_settlement`：只能由白名单剧情结算点写入，普通行动禁止直接写入。

## 6. 18项行动的详细规则

### A01 接触与会谈

- 初访用于建立联系和识别主要诉求，不能直接获得敏感证词；深谈必须带着一个已知议题进入。
- 同一NPC每日只能执行一次。连续两次没有新增事实、方案或兑现进展时，出现“空谈”状态，关系收益归零；第三次继续空谈，信任-3。
- 标准成功：关系+4，获得1个诉求标签；突破：再获得1条可核线索或引荐。
- 反效果：对象认为被敷衍或威胁，关系-5，可能暂时锁定一个时段。

### A02 借关键人物动员

- 玩家必须先说明“请对方影响谁、传递什么、承担什么公开责任”，不能只有“帮我劝劝”。
- 意见领袖适合打开接触渠道；党员示范适合公开程序与共同利益；宗族协商只对宗族网络有效。
- 标准成功只生成“愿意听取”“愿意参加听证”“口头承诺”等状态，不直接增加签约户。
- 宗族链维持现有剧本逻辑：祠堂替代方案被理解后可在口头承诺节点结算+2；正式用地获批后再结算+4，并分别设置首次锁。

### A03 公开听证与政策说明

- 会前必须生成议题清单，并区分“已有明确答案”“需会后核验”“无权当场承诺”。
- 标准成功：信任+4、媒体风险-3、程序完整度提升；同时把现场新问题写入公开台账。
- 若公开政策缺具体价格，可召开“事实与程序说明会”，但不能伪装成最终补偿听证。
- 隐瞒已知矛盾或临时改口：信任-6、媒体风险+8，相关NPC夜间形成联合质疑。

### A04 调整统一补偿方案

- 玩家先选择调整对象：房屋、宅基地、土地、搬迁过渡、签约奖励或安置方式，系统实时显示涉及户数与最大预算敞口。
- 执行只产生“政策草案”和预算预占；A07或A10取得权限后才成为可报价版本。
- 统一标准变化作用于同类全部家庭，不允许只给某一户改统一单价。
- 标准成功：政策可信度由信任指标体现，信任+3；若预算预占超过可用预算，预检直接阻断。

### A05 制定个案安置与生计包

- 系统先展示该户的法律权益、生活需求、偏好、未核材料和与相似户的差异。
- 允许组件：现金权益、安置房、低楼层/无障碍、就学衔接、就业、培训、经营恢复、迁坟/祠堂非现金安排。
- 每个差异化组件都必须选一个理由代码：人口、产权、经营损失、医疗无障碍、就学、历史承诺或经核验的特殊困难。
- 方案送出前自动与三户最相近案例比较。无理由的明显高配会使其他相似户信任-3并产生攀比事件。
- 房源、岗位、培训名额在方案被接受时预占，正式合同或服务交付时消耗。

### A06 困难与医疗救助

- 使用独立救助账，不改变房屋、土地等法定补偿单价。
- 标准成功：建立救助案号，信任+3；医疗复查可解锁健康事实，但诊断结果不由玩家预设。
- 紧急医疗预约可立即占用名额，费用在服务发生时结算。
- 将救助作为“签字交换条件”会触发廉政-8、媒体风险+5，并使对象关系恶化。

### A07 召开专题班子会

- 玩家必须提交一个议题、证据摘要和2~3个互斥方案；系统显示各部门的倾向和权限。
- 会议可授予预算上限、审计授权、法律支持、跨部门人员或媒体口径。
- 标准成功取决于材料质量与政治资本；被否决也必须给出明确理由和补正条件。
- 同一议题没有新增材料时再次开会，默认无效并使干部不满+3。

### A08 约谈干部

- 约谈界面要求玩家选择具体矛盾，例如账实不符、样本处理、历史承诺、签字程序或信息泄露。
- 标准成功：得到一份带时间、人物和可核细节的陈述；突破可得到原始材料位置或第二名知情人。
- 友好提醒、正式约谈、质证三个语气可影响关系和信息深度，但都不能越过证据规则。
- 未持线索的强硬质证：政治资本-3、对象对抗压力+2。

### A09 启动核查与问责

- 第一步永远是核查立案，不是直接处分。需要两条独立线索，或一条具备原件、来源和保管记录的强证据。
- 启动时封存相关材料、指定回避人员、设置调查期限；夜间反制事件根据是否完成封存决定。
- 查实：廉政+8、信任+4，涉事人员权限受限；查否：公开说明结论，避免无限悬案。
- 证据不足强行问责：政治资本-8、干部不满+10、关键干部可能停止合作。

### A10 正式协调

- 每次协调必须填写“事实、已做工作、需要上级决定、最迟时限”四段式简报。
- 张莉模式适合取得专业部门或跨层级接口；县委模式适合县级权限、部门协调与县级资金；市级模式只处理县级明确无法决定的事项。
- 标准成功不是一句“领导重视”，而是批示、责任部门、额度、期限或书面退回理由。
- 越级且本级工作为空：政治资本-5；材料扎实且问题确属越级权限：政治资本+3。

### A11 审计账档

- 村账模式适合查当期支付、原始凭证、经手人和异常发票；县档模式适合查历史政策、旧案、批复和先例。
- 玩家必须先选审计问题，系统才返回相关材料，避免“查全部”一次性清空剧情。
- 取得原件后必须选择复制、封存或仅阅览。仅阅览的材料不能直接作为强证据。
- 联合审计模式成本4，但可同时建立“当前账目—历史依据”的完整链条。
- 现有剧本中的1983年迁坟先例、旧账缺口与原始凭证应继续通过对应范围解锁。

### A12 环境与健康取证

- 病历核验提供“谁、何时、什么指标、由谁检测”，只能支持健康事实，不能单独证明污染来源。
- 第三方检测要求记录采样点、时间、封样、运输和实验室；每缺一项降低一个证据等级。
- 联合评估把环境样本、儿童血铅、人群分布和时间线放到同一模型中，才能支持因果方向。
- 保留现有剧本的时间陷阱：排水事件后采样可能无法复原原始污染水平，但可以证明现场存在冲洗行为。
- 未脱敏公开儿童病历：廉政-5、媒体风险+8、相关家庭关系-10。

### A13 保护性证人访谈

- 执行前选择保密程度、记录方式、回访时间和必要的保护措施。
- 标准成功得到单源证词；证词内必须自动拆成可验证的时间、地点、人物和材料线索。
- 只有与A11、A12或另一独立证人印证后，证词才可升级。
- 证人身份泄露会在夜间触发撤回、失联或遭施压事件。

### A14 媒体沟通

- 三个目的：纠正谣言、公开程序、邀请监督。玩家必须选择目的，不能笼统地“找记者施压”。
- 公开材料分为可公开、需脱敏、不得公开三类。
- 准备充分时：媒体风险-5、信任+2，并形成外部监督；材料矛盾时：媒体风险+10、政治资本-5。
- 记者保持独立，不承诺按玩家想要的角度报道。

### A15 现场调查

- 玩家必须先设定最多三个调查问题和路线，随后选择随行专业角色。
- 一次调查最多带回3条观察；需要取样、访谈或调档的内容会生成后续行动，不在现场自动完成。
- 半日行动与同日另一半日行动互斥；调查增加疲劳5。
- 路线与问题匹配时准备度+2；“随便看看”只得到环境描述，不解锁关键事实。

### A16 交叉印证

- 两个来源必须相互独立，例如同一份报告被两个人转述仍算一个来源。
- 一致时提升证据等级；矛盾时生成“待解释矛盾”，并提示最小补证行动。
- 每次只验证一个命题，避免用1点行动把所有线索一次性洗成事实。
- 已验证过且没有新增材料的命题不能重复收费。

### A17 推进法定程序

- 征收审查检查权属、告知、评估、补偿方案、听证和救济渠道；司法申请检查主体、证据、比例原则和送达。
- 标准成功推进一个程序里程碑，不直接移动居民或增加签约。
- 证据保全可以保护账档、样本或现场状态；司法执行必须等待对应文书生效。
- 程序完整时稳定+3、政治资本+2；程序跳步时稳定-10、媒体风险+12。

### A18 冲突降级与现场秩序处置

- 风险分为言语冲突、阻断办公、人员伤害风险、重大公共安全风险四级。
- 调解分流通过分开当事人、确认诉求和建立后续时限降级，不使用“孤立闹事者”标签。
- 现场管控只针对行为和区域，必须记录命令、警告、时间、人员和医疗准备。
- 强制执行仅在A17对应程序完成、现场存在合法执行任务时开放；执行后必然产生信任-8、媒体风险+8、疲劳+10，若有人受伤则进一步触发独立调查。
- 若尚有可行的低强度手段，界面必须展示并要求玩家说明为何升级。

## 9. 夜间NPC联合行动与白天行动的衔接

夜间联合行动不应是随机剧情，而应使用下列判定：

1. **参与资格**：NPC已解锁、当日未失联/受保护、与至少一名参与者存在关系边。
2. **共同议题**：参与者至少共享一个议题标签，如补偿公平、墓地、健康、账目或程序。
3. **触发材料**：白天行动产生了公开信息、承诺、冲突、证据或资源变化。
4. **组织者**：影响力最高且意愿不为负的NPC发起；A02会改变组织者候选。
5. **行动类型**：联合咨询、共同请愿、互相劝说、证据交换、抵制、施压或谣言扩散。
6. **结算规则**：先结算关系和群体立场，再结算信任/稳定/媒体风险；只有达到明确承诺节点才结算签约。
7. **可解释输出**：玩家第二天看到“谁与谁、因何议题、受哪项白天行动影响、产生什么变化”。

例如：

- A03公开了同类户统一规则后，三名程序敏感型NPC可能夜间核对方案；材料一致则信任上升，发现矛盾则形成联合质疑。
- A12取得病历但未脱敏传播，健康家庭可能联合要求说明，媒体风险上升。
- A02通过宗族协商形成祠堂替代共识后，宗族网络先产生口头承诺；正式用地审批完成后才在对应结算点兑现签约。
- A09未先封存账档便约谈涉事干部，相关NPC可能夜间串联、毁证或统一口径。

## 10. 界面与反馈要求

行动卡不再只显示名称与行动点，至少显示：

- 目标与模式；
- 基础成本、阶段后成本、预计耗时；
- 已满足/未满足前置条件；
- 会占用的人员、房源、名额、预算或权限；
- 可能获得的结果类型；
- 主要风险；
- 冷却、每日上限和是否已经无新增价值。

行动完成面板必须按以下格式输出：

```text
行动：环境与健康取证 / 第三方检测
消耗：5行动点（中期倍率1.5后向上取整），采样套件1，车辆1
结果等级：部分成功（5分）
原因：准备度+2，证据+1，对象匹配+2，错过原排水时间-1，疲劳-1
获得：冲洗行为事实E2；新水样E1；“原始污染浓度”仍未知
指标：信任+1，媒体风险+1
后续：需用病历或历史样本交叉印证；实验室报告将在2日后返回
```

## 11. 实施顺序

### 第一阶段：让18项行动真的能结算

1. 建立统一行动结果结构和六阶段生命周期。
2. 接入关系、事实、证据、程序与资源预占。
3. 把签约写入限制为结算点白名单。
4. 先实现A01、A05、A11、A12、A16五条代表性链路。

### 第二阶段：迁移31项旧入口

1. 按映射表把旧入口转换为新行动模式。
2. 将成立专班改为一次性决策，将郑向东汇总改为免费案头功能。
3. 对旧存档保留ID迁移映射，避免读档失败。

### 第三阶段：补NPC夜间响应

1. 建立NPC影响边、议题标签和组织意愿。

3. 输出可解释的因果日志并加入首次结算锁。

### 第四阶段：平衡与内容补全

1. 用36户进行预算压力、房源短缺和名额分配测试。
2. 用前、中、后三阶段分别验证行动点成本。
3. 将占位补偿参数替换为最终确认的游戏政策值。
4. 为每个行动至少编写反效果、无效、部分成功、标准成功和突破五类结果文本。

## 12. 验收标准

- 玩家在行动前能判断“为什么不能做”和“做了可能影响什么”。
- 18项行动中不存在只扣行动点、只返回泛化叙事而无状态产出的正常成功路径。
- 所有补偿、房源、岗位和名额都具有预占与正式消耗状态。
- 普通行动不能直接修改签约户数。
- 同一事实不能通过重复点击A16无限升级。
- 同一户的差异化方案能展示与相似户的比较理由。
- 强制执行在程序不完整时不可用。
- 夜间NPC联合行动能够回溯到具体白天行动、共同议题和关系网络。
- 所有首次性签约、预算和事实结算都有防重锁。
