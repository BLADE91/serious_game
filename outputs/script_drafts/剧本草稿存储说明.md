# 剧本草稿存储说明

`outputs/script_drafts/` 保存章节式生成的创作源、中间结果、最终结果和人工修订版本。Markdown 是创作事实源，JSON 是从 Markdown 抽取出的运行结构。

## 目录结构

```text
outputs/script_drafts/
├── .version_counter
└── v01/
    ├── 00_generation_request.json
    ├── 01_game_settings.md
    ├── 02_chapter_outline.md
    ├── 03_ch01.md
    ├── 03_ch02.md
    ├── 04_merged_before_review.md
    ├── 05_continuity_review.json
    ├── 06a_global.json
    ├── 06b_ch01.json
    ├── 06b_ch02.json
    ├── 06_script_structure.json
    ├── 07_validation_report.json
    ├── final_YYYYMMDD_HHMMSS.md
    ├── script_generate_YYYYMMDD_HHMMSS.json
    └── revisions/
        ├── r01/
        │   ├── 01_game_settings.md
        │   ├── 02_chapter_outline.md
        │   ├── 03_chNN.md
        │   ├── 05_continuity_review.json
        │   ├── 06a_global.json
        │   ├── 06b_chNN.json
        │   ├── 06_script_structure.json
        │   ├── 07_validation_report.json
        │   ├── revision_manifest.json
        │   ├── final_YYYYMMDD_HHMMSS.md
        │   └── script_revise_YYYYMMDD_HHMMSS.json
        └── r02/
            └── ...
```

章节数量决定 `03_chNN.md` 和 `06b_chNN.json` 的实际数量。没有进行修订时不会创建 `revisions/`。

## 文件职责

| 文件 | 产生阶段 | 说明 |
|---|---|---|
| `00_generation_request.json` | 创建版本时 | 保存原始生成参数，供 Web 续跑时复用 |
| `01_game_settings.md` | Call 1，PA Backend | 全局变量、玩家角色、NPC、结局和创作约束 |
| `02_chapter_outline.md` | Call 2，PA Backend | 章节计划、Flag 计划和结局可达性 |
| `03_chNN.md` | Call 3，PA Backend | 单章完整 Markdown，是局部修订的主要目标 |
| `04_merged_before_review.md` | 程序合并 | 01、02、03 的完整合并稿 |
| `05_continuity_review.json` | Call 4，Qwen Flash | 有双重原文证据的事实连续性问题；只报告，不改写 |
| `06a_global.json` | Call 5a，Qwen Flash | 全局结构、NPC 和结局抽取结果 |
| `06b_chNN.json` | Call 5b，Qwen Flash | 对应章节的剧情树抽取结果 |
| `06_script_structure.json` | 程序合并 | 06a 与全部 06b 的合并结果 |
| `07_validation_report.json` | Call 6，程序 | 必要结构和 Markdown 到 JSON 的 ID 提取完整性 |
| `final_*.md` | 最终保存 | 本版本的完整 Markdown |
| `script_generate_*.json` | 最终保存 | 原始生成版的完整结果 |
| `script_revise_*.json` | 修订完成 | 修订版的完整结果 |
| `revision_manifest.json` | 修订管线 | 修订来源、目标、方式、状态和校验摘要 |

当前没有 `05_revision_notes.md`，也没有 `.*.hash` 缓存文件。

## 断点续跑规则

生成器只按文件存在与否决定是否复用，不比较文件内容，也不自动推断下游是否过期：

- 文件存在：直接读取，跳过对应 Call。
- 文件缺失：执行对应 Call 并写回。
- `04_merged_before_review.md`：每次运行都由当前 01、02、03 重新合并。
- `03_chNN.md`：缺少某一章时，Call 3 会复用已有章节并补生成缺失章节。
- `06_script_structure.json`：存在时会直接跳过整个 Call 5；只删除 `06a` 或 `06b` 不会触发抽取。
- `07_validation_report.json`：`validation_version` 为 2 时直接复用。

Web 的“一键生成”始终创建新版本；“续跑”按钮会列出所有缺少 `script_generate_*.json` 的 `vNN` 供用户选择。续跑沿用 `00_generation_request.json`；旧版本没有该文件时，会从已有 `03_chNN.md` 推断章节数，并使用当前表单补足其他参数。

因此，手动修改上游 Markdown 后，应同时删除受影响的下游缓存。例如只修改 `03_ch02.md` 后重跑抽取和校验：

```bash
rm outputs/script_drafts/v01/06b_ch02.json
rm outputs/script_drafts/v01/06_script_structure.json
rm outputs/script_drafts/v01/07_validation_report.json
python run_script_generation.py --chapter --out-dir outputs/script_drafts/v01
```

修改 `01_game_settings.md` 或 `02_chapter_outline.md` 后，通常应删除 `06a_global.json`、`06_script_structure.json` 和 `07_validation_report.json`；只有章节 Markdown 同时变化时才需要删除对应 `06b_chNN.json`。Call 4 需要重跑时还应删除 `05_continuity_review.json`。正式修订管线会自动处理这些依赖。

## 修订版本

Web 和 CLI 的正式修订不会覆盖 `vNN/` 原版，而是在同代目录下创建平级的 `revisions/rNN/`。从 `r01` 再修订时会创建 `r02`，不会嵌套为 `r01/revisions/r02`。

每个修订版先复制 Markdown 源和可复用的 06a/06b，再按目标重建：

| 修订目标 | 重新抽取 | 复用 |
|---|---|---|
| `game_settings` | 06a | 已有 06b |
| `chapter_outline` | 06a | 已有 06b |
| `chNN` | 对应 `06b_chNN` | 06a 和其他 06b |

所有修订都会重新合并 Markdown、执行事实连续性审查、合并 `06_script_structure.json`、执行 Call 6，并生成新的 final Markdown 与 `script_revise_*.json`。

`revision_manifest.json` 的 `status` 依次为 `building`、`complete` 或 `failed`。主要字段包括：

```json
{
  "revision": "r01",
  "parent": "v01",
  "mode": "manual",
  "target": "ch02",
  "feedback": "",
  "changed_files": ["03_ch02.md"],
  "status": "complete",
  "validation": {"valid": true}
}
```

## 版本编号

`.version_counter` 是快速计数状态，不是版本目录的唯一事实源。分配新生成版时，程序取计数器中的 `gen` 与磁盘已有最大 `vNN` 的较大值，再加 1；即使计数器落后，也不会复用已有目录。

- 全新生成：创建新的 `vNN/`。
- 指定已有 `--out-dir .../vNN`：原地断点续跑，不增加版本号。
- 正式修订：在对应 `vNN/revisions/` 下按现有最大编号创建 `rNN`。

## 校验报告

`07_validation_report.json` 当前使用 `validation_version: 2`，包括：

- `structure_validation`：章节、节点、选项、引用、NPC、结局等必要结构是否合法。
- `extraction_validation`：Markdown 中声明的 chapter、choice、npc、ending ID 是否完整进入 JSON。
- `continuity_review`：Call 4 的事实连续性审查结果，仅作为人工检查线索。

`valid` 只表示自动结构与提取校验没有 error，不代表策略张力、教学质量、人物行为或叙事质量已经通过人工评审。

## 最终 JSON

最终结果顶层包含：

```json
{
  "script": {
    "chapter_npcs": [],
    "chapters": [],
    "chapter_endings": [],
    "validation_report": {}
  },
  "full_md": "# 完整剧本...",
  "generation_mode": "chapter",
  "generation_notes": [],
  "revision_round": 0
}
```

前端的版本列表和“最近结果”会同时扫描 `vNN/*.json` 与 `vNN/revisions/rNN/*.json`，并排除 `01` 到 `07` 的中间 JSON 和 `revision_manifest.json`。
