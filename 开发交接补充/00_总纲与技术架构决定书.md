## 0. 文档总纲：《开发交接补充规格》是什么

### 0.1 本套文档的定位

剧本 `20260713剧本完整版v2.md` 是**游戏设计规格（Game Design Spec）**：它用中文把人、事、规则、结局写死，是"设计真理的唯一来源"。但一份剧本不能直接编译成可运行的程序——它没有回答平台、架构、密钥、存档格式、配置文件结构、验收口径这些**软件工程问题**。

《开发交接补充规格》是剧本之外的**软件工程规格（Software Engineering Spec）**。两者的分工是：

| 文档 | 回答什么 | 冲突时谁赢 |
|---|---|---|
| 剧本 md | 游戏"是什么"：剧情、数值、旗标、结局、界面口径 | 涉及游戏设计事实时，剧本赢 |
| 本套补充规格 | 游戏"怎么造"：平台、架构、密钥、存档、配置、验收 | 涉及工程实现决策时，本规格赢 |

**两者合起来，才能万无一失地开发。** 单有剧本，开发者会在一百个工程岔路口各自拍脑袋，最终跑出一百种不兼容的实现；单有工程规格，则无内容可承载。本册（第 00 册）是这套工程规格的**根**：它先把平台与总体架构定死，后续各册在此架构下细化。

## 1. 目标平台与形态裁决

### 1.1 三个不可动摇的约束（先摆约束，再谈选型）

剧本的三条硬性质，直接排除了"纯前端单机"这一整类方案：

| # | 约束 | 剧本依据 |
|---|---|---|
| C1 | **暗档绝不能下发到不可信客户端。** 环评线索 `env_clue`、廉政清白指数 `integrity`、腐败证据 `corruption_evidence` 三项"任何形式一律不上界面"，且要求"藏死"。若这三个变量存在于客户端内存/存档，玩家可用调试器/存档编辑器直接读出，限知视角当场破防。 | 【源自剧本 L2127 / L2130 / L2140】 |
| C2 | **LLM 密钥不能放前端。** 23 个 NPC 由大模型现场生成自由对话（L21），任何前端持有的 API Key 都会被抓包盗用，成本失控。 | 【源自剧本 L21】 |
| C3 | **夜间引擎需后台常驻结算。** "白天行动点用尽，天一黑，二十三个人之间那张网就开始在玩家看不见的地方自己动"（L579），夜戏正文"永不向玩家展示"（L4442），且结算要跑一轮全 NPC 关系网。这是一个**权威结算**过程，不能信任客户端自算自报。 | 【源自剧本 L579 / L4442 / L2248】 |

### 1.2 平台形态：Web 优先，桌面/移动为同一前端的封装

**裁决：目标形态为「响应式 Web 应用（浏览器）」作为唯一一等公民；桌面端与移动端不做原生实现，而是用同一 Web 前端封装（桌面走 Tauri/Electron 壳，移动走 PWA/WebView 壳）。**

【新增设计裁决：本作是纯文字交互 + 地图/关系图面板（§14），无高帧渲染、无重度输入，Web 技术栈完全够用；而 45 分钟一局、23 NPC LLM 对话的核心体验完全由服务端决定，前端只是"渲染 + 采集输入"的薄壳，为三套原生端重复造轮子没有任何工程收益。Web 单前端 + 壳封装可一次覆盖三平台，且与 C1/C2/C3 要求的服务端权威天然契合。】

| 目标平台 | 交付方式 | 说明 |
|---|---|---|
| 桌面浏览器（主） | 直接访问 Web URL | 开发与验收基线，§14 界面按桌面宽屏布局设计 |
| Windows/macOS 桌面 | Tauri 封装同一前端 | 仅加一层壳，不改业务代码 |
| 移动端 | PWA（可加桌面图标） | 竖屏下地图面板/关系网络图折叠为可切换抽屉，符合 L2193「默认收起」口径 |

### 1.3 单机 vs C/S：裁决为 C/S（瘦客户端 + 权威服务端）

**裁决：本作必须是 Client/Server 架构，禁止纯单机。** 由 C1+C2+C3 三条约束联合推出，不存在纯单机的合规实现路径：

- C1 要求暗档不出服务端 → 状态权威必须在服务端；
- C2 要求密钥不出服务端 → LLM 调用必须在服务端；
- C3 要求夜间引擎常驻权威结算 → 结算必须在服务端。

三条各自都指向服务端，联合结论唯一。**【源自剧本 L2127 / L21 / L579，三约束联合推定】**

### 1.4 拍板架构：瘦客户端 + 服务端（LLM 代理 + 夜间引擎 + 结算权威）

```
┌─────────────────────────── 瘦客户端（浏览器 / 壳）───────────────────────────┐
│  职责：渲染 §14 九节界面、采集玩家决策与自主动作、播放五层音效               │
│  持有：仅"玩家可见态"——台账档 4 项数字、体感档 5 项档位词、地图色块、        │
│        关系图已知连线、事件日志、晨间卡（读完即焚）                          │
│  绝不持有：任何暗档原值、任何指标底层数值、任何旗标真假、任何轴值、LLM 密钥   │
└──────────────────────────────────────────────────────────────────────────────┘
                    │  HTTPS（仅传"投影后的可见态"与玩家输入）
                    ▼
┌─────────────────────────────── 权威服务端 ────────────────────────────────────┐
│  ① 会话/状态权威：十项指标 + 腐败证据 + 全部旗标的唯一真值，钳制在此执行       │
│  ② LLM 代理：持有密钥，注入 23 NPC 人格与神情，限流/成本归属在此（见 §3）     │
│  ③ 夜间引擎：行动点耗尽后触发，跑全 NPC 关系网结算，写回状态（见 §2.2）       │
│  ④ 结算权威：剩余天数归零 → 冻结 → 算 14 轴 → 比 24 行主结局表 → 出亚结局     │
│  ⑤ 可见态投影器：把权威状态"投影"成客户端可见态（数字降为档位词、暗档剔除）   │
│  ⑥ 持久化：玩家存档 + 研究数据双库（见 §4）                                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**关键设计原则——"投影而非下发"**：服务端持有全部真值，但发给客户端的永远是**投影后的可见态**。例如体感档服务端存 `public_trust=62`，投影器按§14.1 五档词表映射，只把字符串 `"观望"` 发给前端；暗档三项在投影时直接剔除，前端连字段都收不到。**【源自剧本 L2115「永不显示底层数值」/ L2119-2123 五档词 / L2127 暗档不可读】**

## 2. 服务端核心子系统的架构位

### 2.1 LLM 代理（白天自由对话）

- 位置：服务端 ②。前端把玩家对某 NPC 说的话 + 当前场景上下文发给服务端，服务端组装 Prompt（注入该 NPC 的九维档/性格五维/当前信任档/神情），调 LLM，把生成的台词 + 神情词回传前端。
- 前端拿到的只有"台词 + 神情词"，拿不到信任度数值。**【源自剧本 L2136「人物信任度不给数字」/ L971】**
- 具体 Prompt 结构、人格注入、四档吐真深浅由第 50 册规定。

### 2.2 夜间引擎（后台权威结算）

- 触发：某玩家会话的当日行动点"扣到不足以支撑下一个动作"即入夜。**【源自剧本 L2248 / L2162】**
- 执行：服务端遍历 23 NPC 关系网，跑一轮 NPC 间自主对话/传话/结盟/翻脸，更新各人信任/态度/焦虑，回写权威状态。**【源自剧本 L579 / L4439】**
- 边界（第 40 册细化，此处定架构位）：夜间引擎**只能**改指标数值、NPC 关系值、以及已登记旗标；不得开启未登记旗标，不得让必然事件（血铅、巡察组）不发生，不得替玩家做决策点选择，不得改玩家已定旗标。**【源自剧本 L4440-4441】**
- 产物二分：给玩家的只有一张"三行以内、无数字、读完即焚"的晨间卡；夜戏全文 + 关系值变化单独落研究库（见 §4.3）。**【源自剧本 L4442-4443 / L4448-4451】**

### 2.3 结算权威（结局判定）

- 唯一入口：剩余天数归零。先冻结全部指标 + 腐败证据 + 旗标，判定期间任何一处不得再写。**【源自剧本 L2252】**
- 流程：算 14 轴 → 自上而下比 24 行主结局表、首行命中即停、末行恒真兜底 → 读主结局声明的自由轴落到 95 亚结局之一 → 3 个附加位只改收尾文本。**【源自剧本 L2252】**
- 明令禁止：不设综合评分、不设 85/70/55/40 四道坎、不设六步短路链、不设指标阈值分箱、不设全面失败旗标。这些"不存在物"由第 70 册写成回归测试断言，防止实现者手滑加回来。**【源自剧本 L2240 / L2252】**

## 3. LLM 调用归属：谁调、密钥放哪、限流与成本

| 维度 | 裁决 | 依据 |
|---|---|---|
| 谁调 | **只有服务端 LLM 代理调**，前端一次都不直连模型厂商。 | 【源自剧本 L21 + 约束 C2】 |
| 密钥放哪 | 模型 API Key 只存服务端环境变量/密钥管理服务，永不进代码仓库、永不进前端包。 | 【新增设计裁决：抓包即盗，前端持密钥等于公开密钥】 |
| 限流 | 按玩家会话（session）限流：每会话每分钟的 LLM 调用数设上限，超限则前端提示"对方在斟酌"并排队，不允许并发轰炸。 | 【新增设计裁决：单局 45 分钟、决策密度有限，会话级限流足以挡住脚本刷量而不影响正常玩家】 |
| 成本归属 | 成本按会话计量落研究库，服务端为唯一计费点；夜间引擎的批量 NPC 结算与白天对话分开计量，便于第 70 册核算每局 token 成本。 | 【新增设计裁决：夜间全网结算是成本大头，必须与白天对话分账才能定容量】 |
| 降级 | LLM 超时/失败时，白天对话回退到"该 NPC 沉默 + 一句神情描写"，绝不把错误信息或空串暴露给玩家；夜间引擎失败则该夜按"无事发生"处理并记研究库异常，必然事件仍照常在其日程触发。 | 【源自剧本 L4440 必然事件不可因夜间波动而不发生】 |

## 4. 存档架构

### 4.1 三选一拍板：云端账号存档

**裁决：采用「服务端云端账号存档」，排除本地文件与 localStorage。**

| 候选 | 是否采用 | 理由 |
|---|---|---|
| 本地文件 / localStorage | **否决** | 暗档、旗标真假、轴值一旦落到客户端可存取的介质，玩家可读可改，违反 C1"藏死"。存档必须与权威状态同处服务端。 |
| **云端账号存档** | **采用** | 权威状态本就在服务端（§1.4），存档就是服务端对该会话权威状态的持久化，天然满足暗档不落客户端。 |

**【源自剧本 L2127 暗档藏死 + L1.4 权威在服务端联合推定】**

> 客户端本地只允许缓存"当前可见态"用于断线重连时的瞬时重绘，且该缓存不含任何暗档/旗标/数值，掉了也能从服务端重投影恢复。

### 4.2 存档时机与槽位

| 决策 | 裁决 | 依据 |
|---|---|---|
| 存档时机 | **每决策点后 + 每日结算（入夜结算）后各落盘一次**，随进度自动落盘，无手动存档按钮。玩家中途离开，回来接着上一步。 | 【源自剧本 L2169「存档随进度自动落盘，玩家中途离开，回来还接着上一步」】 |
| 单槽 vs 多槽 | **单账号单局单槽（自动续玩槽）**，进行中的一局只有一份权威存档，自动覆盖式续写。 | 【源自剧本 L2169 语义为"续玩"，非"多存档回溯"】 |
| 多周目 | **支持多周目：一局走到结局后归档为只读周目记录，玩家可开新局。** 新局重置十项指标为初值、全旗标为假。 | 【新增设计裁决：24 主 × 95 亚结局的重玩价值要求可重开新局；但进行中的局仍是单槽，不提供中途分支回档，以保限知视角"没记住就是没记住"的一次性张力（L4451）】 |

### 4.3 双库分离：玩家存档库 vs 研究数据库

**裁决：玩家存档与硅基社会研究数据物理分两库。**

| 库 | 装什么 | 依据 |
|---|---|---|
| 玩家存档库 | 权威状态快照（供续玩）：十项指标 + 腐败证据 + 旗标 + NPC 状态 + 已发生事件日志 + 地图/关系图已知事实 | 【源自剧本 L2211 事件日志入档口径】 |
| 研究数据库 | 夜间引擎生成的 NPC 间对话全文、关系值变化、及其与玩家白天行为的相关性 | 【源自剧本 L4443「这一部分数据不进玩家的存档，单独落库」】 |

晨间卡不进任何库——读完即焚，不可回看、不进日志、不进档案。**【源自剧本 L2217 / L4451】**

## 5. 内容 / 引擎分离：数值·结局·旗标·价目全部外置为 JSON

**裁决：引擎代码不硬编码任何游戏数值，一律读外置 JSON 配置。** 剧本§15 明令"常量集中定义、全局引用，不许在任何一处出现第二个版本"，中英键映射"集中在一张对照表里"——这本质上就是"配置外置"的要求。**【源自剧本 L2254】**

### 5.1 外置配置清单

| 配置文件 | 内容 | 供应册 | 剧本依据 |
|---|---|---|---|
| `numbers.json` | 十项指标 + 腐败证据的初值/量程/钳制；三档行动点倍率（1.0/1.5/2.0）；从众阈值；信任四档边界（0-25/26-50/51-75/76-100） | 10 | 【L2238 / L2244 / L2248】 |
| `flags.json` | §7.5 全部登记旗标：键名、初值假、置真点、读取点、锁定语义 | 20 | 【L995 / L2242】 |
| `endings.json` | 24 行主结局表（含行序 = 仲裁规则、末行恒真兜底）+ 95 亚结局 + 3 附加位文本 | 40/70 | 【L2252】 |
| `axes.json` | 14 条轴的定义与算法输入（只读选项事实/自主动作事实/NPC 终局态） | 40 | 【L2252】 |
| `actions.json` | 玩家自主动作基准点数与回写 | 30 | 【L2153 / L2248】 |
| `events.json` / `night_scenes.json` | 突发事件触发器、夜戏触发条件与回写 | 40 | 【L2250 / L4411-4435】 |
| `key_map.json` | 中文名 ⇄ 英文键唯一对照表（界面/叙事用中文，存储/逻辑用英文键） | 全册共用 | 【L2254 / L974】 |
| `constants.json` | 承重常量：36 户 / 30 户线 / 6000 万底线 / 500 米 / 90 天 / 8000 万预算 / 每日 8 点 | 全册共用 | 【L2254】 |

### 5.2 引擎读配置的铁律

- 引擎逻辑与跨章条件**只许读取 `flags.json` 登记在册的旗标**；剧情里置真却未登记的旗标只作存档记录，引擎不据以判定。**【源自剧本 L995 / L2242】**
- 支持内容热更/迭代：改数值、调结局阈值、加旗标只改 JSON，不改引擎代码、不重编译。**【新增设计裁决：补 S9——数值与结局表是最需要平衡性迭代的部分，外置 JSON 使策划可独立于工程改动做灰度调参；引擎只认 schema，配置版本化管理】**
- 配置加载时做 schema 校验 + 一致性校验（如"无剧情读取一个从未被置真的旗标"），校验不过则拒绝启动。**【源自剧本 L2242 / L2254 第九条一致性校验】**

## 6. 本地化范围：仅简体中文，不做 i18n 架构

**裁决：本作只出简体中文，工程上不引入 i18n 框架、不做字符串抽取、不做多语言资源包。** **【新增设计裁决：补 S8】**

理由（写清楚为何不做，避免后人误加）：

1. **内容与语言深度耦合**：游戏体验建立在中文官场语感、顿号/中点/直角引号「」的排印口径、以及"搬迁率三字禁令"（L2112）一类逐字规约之上；这些是无法翻译的设计资产，翻译即失真。
2. **LLM 人格靠中文语料**：23 NPC 的说话口吻由中文性格描写驱动（L2244 性格五维约束口吻），换语言等于重做人格。
3. **成本收益**：i18n 架构会给每个界面字符串加一层抽取/查表开销，而本作无海外发行目标，纯属负担。

工程落点：界面字符串直接以简体中文内联；`numbers.json`/`flags.json` 等配置的展示名一律中文；`key_map.json` 中英对照仅用于"中文展示 ⇄ 英文存储键"，**不是 i18n**，不得被误当作多语言层扩展。

## 7. 无障碍底线

**裁决：以下两条为强制底线，第 60 册 UI 实现必须满足，验收（第 70 册）逐条勾验。**

### 7.1 字号可调

- 全界面文字支持至少三档字号（标准 / 大 / 特大），主舞台叙事区、决策点选项、晨间卡一体缩放，布局按相对单位（rem/em）实现，放大后不溢出、不裁字。**【新增设计裁决：本作是纯文字叙事游戏，阅读舒适度是核心可达性，字号可调是最低门槛】**

### 7.2 四色地图必须附图案/文字冗余（不得只靠颜色区分）

§14.5 地图面板用绿/红/黄/灰四色区分四种户状态，纯色对红绿色盲不友好。**要求四色各自叠加一个图案 + 文字标签冗余**，使不辨色者也能区分：**【源自剧本 L2181-2186 四色状态 + 新增设计裁决：四色含红/绿，红绿色盲无法区分，必须加非颜色通道】**

| 状态 | 颜色 | 追加图案 | 追加文字 |
|---|---|---|---|
| 已签约 | 绿 | 实心勾 ✓ | 门牌旁标"签" |
| 明确拒绝 | 红 | 实心叉 ✕ | 门牌旁标"拒" |
