# 文档导航

仓库文档按“权威剧本、游戏设计、开发规格、产品资料、项目材料、历史归档”划分。运行时代码自己的接口和验收文档继续放在 `code/backend/docs/`，避免脱离实现。

## 游戏设计

- `game_design/需求清单.md`：剧本与玩法需求清单。
- `game_design/script_quality_standard.md`：剧本质量与交付标准。
- `game_design/conflict.md`：最终剧本与开发规格冲突清单。
- `game_design/optimization/optimization1.0.md`：内容与玩法优化决策。
- `game_design/optimization/D75_补签冲突定稿.md`：D75–D90 补签与冻结规则。
- `game_design/剧本写作参考.md`：理论、案例与创作资料。
- `game_design/story_tree_45min_analysis.html`：早期 45 分钟剧情树分析。

## 开发资料

- `development/specs/`：开发交接补充规格，共四册。
- `development/llm_token_max_estimate.md`：角色 LLM Token 上限预算。
- `../code/MILESTONES.md`：当前代码里程碑与验收状态。
- `../code/backend/docs/`：玩家 API、语义闭环、LLM 和研究治理记录。

## 产品与项目材料

- `product/`：产品需求、技术设计、测试计划、美术需求与参考图。
- `project_materials/`：项目提案、资助申请、研究汇报和早期设计文档。
- `archive/`：早期长文档及已被正式后端取代的开发任务说明，仅供追溯。

仓库根目录的 `最终剧本.md` 保持原路径，因为剧本包构建工具和自动化测试以它作为内容权威输入。
