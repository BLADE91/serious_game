## 10.1 五项体感指标：数值 → 档位词 切分点表

**问题现状**：剧本 L682–686 只给出每项五档词、未给数值边界。引擎拿到「民众信任度 = 57」不知道该显示哪个词。

**裁决范式**：照人物信任度四档切分（L770–775 的整数闭区间写法 `0–25 / 26–50 / …`）扩成五档，均分 0–100 为五段，**每段 20 点**：`0–20 / 21–40 / 41–60 / 61–80 / 81–100`。【新增设计裁决：五档词梯 + 人物信任度整数区间范式的直接外推；每档 20 点亦与 §10.3「每档=20点」自洽】

**关于「反向指标」的关键澄清**：剧本 L682–686 的五档词梯**本身已按数值升序书写**（一档 = 数值最低，五档 = 数值最高）。对正向指标，数值高 = 词好；对反向指标（舆论压力、领导班子不满度），数值高 = 词坏——但两类的词表列序都与「数值由低到高」一一对应。因此**档位词的选取对五项完全统一：按数值落在哪一段取该段序号的词，无需翻转**。剧本 L2125 所说「反向指标进度条的填充方向由代码层定」只约束**进度条填充方向**（视觉长度），不影响档位词选取。【源自剧本 L682–686, L2125】【新增设计裁决：明确「反向」只翻转进度条填充、不翻转档位词映射】

## 10.2 区间「X 到 Y」落值规则 + 「判定系数」澄清

### 10.2.1 先澄清「判定系数」不是随机系数

全书结算块出现 60 处「判定系数」字段。核查其实际用法：

- L2437 / L3200：`判定系数：不设。`
- L3571：`判定系数：选项A与选项B均为查案倾向，进入反腐线权重。选项C为回避，进入签约线权重。选项D为对抗，同时抬高对抗类结局的权重。`

**结论**：该字段是**叙述性的结局线倾向说明**——描述本决策点各选项把玩家推向哪条结局线（反腐线 / 签约线 / 对抗线…），是给策划与结局排列组合读的定性说明，**与随机数、概率、乘法系数毫无关系**，也不参与任何数值运算。【源自剧本 L3571, L2437, L3200】

**开发提醒**：字段名沿用剧本原名 **「判定系数」**（不更名）。但须注意「系数」二字仅为历史命名，**不得**据此实现任何随机 / 加权乘数。46 处 `判定系数：不设` 一并按「本点无结局线倾向说明」处理，引擎侧**不为此字段分配任何数值变量**。【新增设计裁决：保留剧本原名「判定系数」，仅在注释中澄清其为叙述性字段、非数值系数，以消除「系数=随机/加权」的误读】

> 重申红线：结局不读指标、不做区间分箱（L704–706, L3572）。此字段只是给结局排列组合看的标签。

### 10.2.2 确定性落值规则（核心）

**现状**：全书约 34 处结算写成「上升 8 到 12」「下降 200 到 400 万元」这类**区间**，另有区间横跨正负的写法（如 L3197「政治资本变动区间为下降 2 到上升 5」）。区间不落值 → 破坏「同输入同输出」。

**裁决（唯一落值公式）**：【新增设计裁决：中位数向上取整，纯确定性、无随机源、可复现】

```
落值 Δ = ceil( (X + Y) / 2 )
```

其中 `X` = 区间下界（带符号），`Y` = 区间上界（带符号）。方向词（上升/下降、+/−）先转成带符号数再代入。落值后再按该指标量程钳位（§10.0）。

- 「上升 A 到 B」→ X=+A, Y=+B。
- 「下降 A 到 B」→ X=−A, Y=−B。
- 「变动区间为下降 A 到上升 B」→ X=−A, Y=+B（跨零）。

**为什么向上取整**：使奇数中位数（如 12.5）有唯一确定值，避免「四舍五入」在 .5 处的实现分歧；全书统一 `ceil` 一种舍入方向即可复现。

| 出处 | 原文区间 | 带符号 X, Y | (X+Y)/2 | 落值 Δ = ceil |
|---|---|---|---|---|

| L3198 财政预算 | 下降 200 到 400 万元 | −200, −400 | −300 | **−300 万元** |

### 10.2.4 若某处确需随机（预留，当前不启用）

本作默认**全确定性**，上表规则覆盖全部区间，无需随机。若未来某决策点确需引入随机分布，**随机源必须可复现**：

```
seed = hash( 存档种子 saveSeed  ⊕  决策点ID decisionPointID )
```

同一存档、同一决策点，`seed` 恒定 → 重放一致。**禁止**使用系统时钟、真随机、全局 RNG 序列位置等不可复现源。【新增设计裁决：确定性随机源 = 存档种子 ⊕ 决策点ID 的哈希，保证可复现】

## 10.3 体感内部表示裁决（三套模型合一）

**现状：三套模型并存**——
- §7.1：体感为 0–100 连续值（L657–669）；
- L696：「按档记涨落 / 一次至多挪三档」离散五档；
- 各章正文：「上升 6 到 10」这类连续增量。

**拍板（单一事实源 = 点数）**：【新增设计裁决：以 §7.1 量程为内部唯一存储，L696 降级为显示层规则，理由见下】

| 层 | 表示 | 规则 |
|---|---|---|
| **内部存储** | `int` 0–100（§7.1 量程为准） | 一切增减先落成点数（§10.2 落值），累加进点数，最后钳到 [0,100] |
| **显示层** | 五档词（§10.1） | 每档 = 20 点；「挪一档」= 显示词跨过一个 20 点边界；界面只显当前所在的那一个词（L678, L696 末句） |

**L696「幅度词 → 档步」重述为「幅度词 → 点数」**：正文若只写幅度词、不带数值区间时，按下表折成点数增量（1 档 = 20 点），再走内部点数累加；正文若已给数值区间（如「上升 6 到 10」），直接用 §10.2 落值，**不再走幅度词换算**（二者择一，数值区间优先）。【源自剧本 L696；【新增设计裁决：把 L696 的「档步」按 1档=20点 折算为点数，使其与连续增量统一到点数模型】】

| 正文写法 | 档步（L696） | 折算点数 |
|---|---|---|
| 升 / 降 / 涨 / 跌（不带幅度词） | 1 档 | ±20 |
| 小幅 | 1 档 | ±20 |
| 大幅 / 大涨 / 大跌 / 骤降 / 上冲 | 2 档 | ±40 |
| 重挫 | 3 档 | ±60 |
| 明写「升/降 N 档」 | N 档 | ±20N |

**「一次至多挪三档」的重新定性**：L696 原文「一次结算至多挪三档，挪到顶档或底档即止」。在点数模型下——
- 「挪到顶档或底档即止」= 内部点数**钳到 [0,100]**（每次结算恒执行，源自 §7.1 与 L696）；
- 「至多挪三档」= **单次结算对单一指标的净点数变化幅度 ≤ 60（=3档×20点）**。因幅度词最大为「重挫」=3档=60、数值区间落值亦均在此内，此约束是一条**建表/校验不变量**（校验用），并非把内部点数二次截断的运行时规则。若某次结算叠加多个子效应导致单指标 |ΣΔ| > 60，视为**剧本/建表缺陷需报警**，而非静默削平——**不改内部点数**（与任务裁决一致）。【源自剧本 L696；【新增设计裁决：把「挪三档」落为校验不变量而非运行时截断，以维持内部=显示一致】】

### 10.3.1 内部点数 ↔ 显示档位 双向换算

**点数 → 档位（显示时）**：
```
档序 = max(1, ceil(value / 20))       // value 已钳 [0,100]，见 §10.1
```

**档位 → 点数区间（反查 / 建表校验时）**：

| 档序 | 点数闭区间 | 边界点 |
|---|---|---|
| 一档 | 0–20 | 下边界 0，上边界 20 |
| 二档 | 21–40 | |
| 三档 | 41–60 | |
| 四档 | 61–80 | |
| 五档 | 81–100 | |

> 档位 → 点数是「一对多」（一个档对应 20 个点值），仅用于校验「某点数是否落在预期档」，**不可**用于把档位反推成单一点数（内部永远以点数为准，不从档位回写点数）。【新增设计裁决：禁止档位回写点数，杜绝显示层污染存储层】

**位移示例**：民众信任度内部 58（三档「观望」），本次结算「大幅上升」=+40 → 58+40=98（钳内），显示跨「观望→配合→亲近」两个边界 = 挪 2 档，落「亲近」。位移 2 档 ≤ 3 档，校验通过。

## 10.4 中央增减量表（结构规范 + 抽取指引）

**现状**：增减量散在各章 `:::代码` 结算块的散文结算行里，无集中表 → 难校验、难复现、易与散文冲突。

**裁决**：建立单一《中央增减量表》，声明**「散文结算行与本表冲突时，以本表为准」**。【新增设计裁决：集中表为增减量唯一事实源，散文降级为叙事说明】本篇给出**表结构、字段定义、抽取方法与样例模板**；不手工抽全约 356 条，由开发者按 §10.4.3 方法批量建表。

### 10.4.1 主表结构

主键：`(章, 决策点/事件编号, 选项)`。值：各指标已按 §10.2 落成**单值**的 Δ，以及旗标 set/clear 动作。

| 字段 | 类型 | 说明 |
|---|---|---|
| `chapter` | int | 章号（1–6） |
| `node_id` | string | 决策点/事件编号，如 `EV1-01`、`EV1-02`、`DP2-01` |
| `option` | enum | 选项字母 `A/B/C/D`（无选项的自动事件填 `-`） |
| `precondition` | string | 触发/可选性前置（如 L3194–3195），无则 `恒成立` |
| `delta.public_trust` | int | 民众信任度 Δ（§10.2 落值；无变动填 0） |
| `delta.social_stability` | int | 社会稳定度 Δ |
| `delta.political_credit` | int | 政治资本 Δ |
| `delta.media_pressure` | int | 舆论压力 Δ |
| `delta.cadre_discontent` | int | 领导班子不满度 Δ |
| `delta.integrity` | int | 廉政清白指数 Δ（暗档） |
| `delta.env_clue` | int | 环评线索 Δ（暗档） |
| `delta.budget` | int | 财政预算 Δ（万元） |
| `delta.signed` | int | 签约户数 Δ（按户群整数，见 L647；不入账填 0） |
| `delta.corruption_evidence` | int | 腐败证据 Δ（暗档，含「针对玩家自身」子目） |
| `flags_set` | string[] | 本选项开启的旗标名 |
| `flags_clear` | string[] | 本选项关闭的旗标名（关闭不退分，L791） |
| `判定系数` | string | 判定系数原文（叙述性结局线倾向说明，§10.2.1；`不设` 留空） |
| `notes` | string | 条件分支备注（如「若已开旗标 X 则取上限」等散文条件，见下） |

**条件分支处理**：部分结算行是**条件化**的（如 L3196「若此前已开启旗标困难户帮扶…则…否则…」、L3199「若廉政清白指数已受损…舆论压力取上限」）。这类拆成**多行**，每行一套前置 + 一套落值，用 `precondition` 字段区分；`notes` 记「取上限/取下限」等偏置。【源自剧本 L3196, L3199】

### 10.4.3 抽取方法（建表指引）

1. **逐章扫描 `:::代码` 结算块**：每个决策点/事件的机读规则都封装在 ` :::代码 … ::: ` 围栏内（见 L2428 起 EV1-01、L3190 起 EV1-02）。以围栏为单位遍历。
2. **定位字段**：块内按行取——`编号：` → `node_id`；`前置条件：`/`选项可选性约束：` → `precondition`；`选项X结算：` → 该选项行；`判定系数：` → `判定系数`（叙述性字段，§10.2.1）；`结局权重：`/`连锁反应：` 不进本表（属结局与流程层）。
3. **解析结算行**：在「选项X结算」句中，按「指标名 + 方向词（上升/下降/保持不变）+ 区间/单值」抽取，方向词定符号，区间走 §10.2 `ceil` 落值；「保持不变」= 0；「开启旗标：」→ `flags_set`，「关闭旗标：」→ `flags_clear`。
4. **拆条件分支**：遇「若…则…否则…」拆成多行（§10.4.1）。
5. **落值即固化**：抽取时立即执行 §10.2 落值，表内只存单值整数，不留区间。
6. **签约户数特判**：签约走户群整数（L647），以《签约阶层户数表》为唯一口径；结算行写「带动某户群 N 户」时 `delta.signed = N`，写「不入账/本章不结算户群」时填 0（L3198）。
7. **校验**：每行过 §10.3「单指标 |ΣΔ| ≤ 60」不变量；越界报警。全表建成后，散文结算行仅作叙事，数值以本表为准。
