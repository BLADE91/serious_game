# 严肃游戏剧本质量标准与交付模板

本文档用于约束剧本生成器的初稿输出和后续人工编辑流程。目标不是一次生成文学终稿，而是稳定产出一份可评审、可修改、可进入游戏制作的剧本制作包。

## 适用目标

剧本初稿必须支撑后续游戏制作，而不只是提供故事文本。合格初稿应同时服务于：

- 剧作编辑：判断主题、人物、冲突和叙事节奏是否成立。
- 游戏设计：确认节点、选择、后果、变量和结局是否可玩。
- 前端制作：提取章节、场景、信息节点、选项和反馈文案。
- 规则实现：消费变量变化、flag、NPC 状态和结局条件。
- 教学复盘：解释玩家选择与治理结果之间的因果关系。

## 初稿验收原则

第一版初稿不追求完美，但必须满足以下原则：

- 主题清楚：玩家能明确知道自己面对的核心治理问题。
- 主线完整：剧情从压力进入、矛盾升级、危机爆发到结果收束。
- 角色可用：关键 NPC 有诉求、底线、资源、关系和转变条件。
- 选择有张力：没有明显标准答案，每个选项都有收益和代价。
- 后果连续：前序选择会影响后续信息、NPC、变量、节点或结局。
- 结局可解释：每个结局能回溯到玩家的治理风格和关键选择。
- 制作可拆分：章节、节点、选项、结果、变量和文案可以被单独编辑。

## 质量评分标准

每项 1-5 分，总分 40 分。低于 3 分的单项必须进入人工修改；总分低于 32 分不建议进入后续制作。

| 维度 | 5 分标准 | 常见扣分点 |
|---|---|---|
| 教学目标明确性 | 每章、每个关键决策和每个结局都能对应具体学习点 | 目标停留在口号，无法对应玩家行为 |
| 治理困境真实性 | 冲突来自制度、资源、利益、人情和时间约束 | 为戏剧冲突而冲突，缺少现实治理逻辑 |
| 角色驱动力 | NPC 行为由诉求、处境、关系和底线推动 | NPC 只服务剧情推进，缺少稳定动机 |
| 选择张力 | 每个关键选项都有合理收益、真实代价和延迟后果 | 出现明显正确答案或纯惩罚选项 |
| 后果连续性 | 前序选择会改变后续节点、信息、NPC 态度或结局路径 | 每章像独立短故事，选择影响只停留在当前段落 |
| 数值合理性 | 变量定义清晰，变化尺度稳定，阈值能触发具体事件 | 数值随意加减，缺少叙事含义和机制含义 |
| 结局可解释性 | 结局由变量、flag、NPC 状态和玩家策略共同决定 | 最后只按简单阈值判定，缺少路径解释 |
| 制作可用性 | 文本、节点、选项、场景、变量和反馈能直接拆给制作侧 | 只有长篇叙事，缺少结构化制作信息 |

## 必备交付物

最终剧本应以固定结构输出，可以先使用 Markdown 承载，再由后端抽取结构化 JSON。

### 1. 项目概览

- 标题
- 目标游戏时长
- 玩家角色
- 核心主题
- 教学目标
- 体验关键词
- 推荐玩家人数与单局节奏

### 2. 世界观与背景

- 政策背景
- 地域与时代设定
- 核心冲突
- 主要压力来源
- 已知事实与合理虚构边界

### 3. 角色表

每个关键 NPC 必须包含：

- npc_id
- 姓名
- 身份与所属群体
- 核心诉求
- 底线
- 可被说服或激化的条件
- 掌握的信息
- 与其他 NPC 的关系
- 初始态度
- 可能的态度变化路径

### 4. 变量与机制表

每个变量必须包含：

- 变量名
- 中文含义
- 初始值
- 合理范围
- 变化尺度说明
- 关键阈值
- 触发事件
- 对结局的影响

变量变化必须有现实含义。例如，`public_trust +10` 需要对应明确的群众信任提升事件，而不是抽象奖励。

### 5. 章节设计

每章必须包含：

- chapter_id
- 章节标题
- 时间范围
- 本章核心任务
- 本章学习目标
- 场景背景
- 信息节点
- 2-4 个关键决策点，或明确说明为什么本章只需要 1 个主决策点
- 每个决策点 3-5 个选项
- 每个选项的即时后果、长期影响和教学反馈
- 章节结算摘要

### 6. 分支与状态追踪

每个玩家选项必须记录：

- choice_id
- 所属章节与决策点
- 可用条件
- 变量变化
- flag 新增与移除
- NPC 状态变化
- 解锁节点
- 关闭节点
- 结果节点
- 长期影响说明

分支影响必须能在后续章节中被看见，不能只停留在当前结果文本里。

### 7. 结局设计

每个结局必须包含：

- ending_id
- 标题
- 类型：good / neutral / bad
- 触发条件
- 必须包含或避免的关键 flag
- 关键 NPC 状态要求
- 叙事文本
- 玩家策略画像
- 教学复盘

结局判定不能只依赖单个变量阈值。至少应综合变量、flag、关键选择和 NPC 状态。

### 8. 制作备注

剧本应补充制作侧可用信息：

- 关键场景
- 重要道具或文件
- UI 表现建议
- 音效和氛围建议
- 需要美术或前端重点表达的情绪变化
- 仍需人工补充的问题

## 初稿生成要求

生成器输出初稿时，应优先保证结构完整和因果清楚，再追求文采。具体要求：

- 不输出纯小说文本。
- 不把教学反馈写成说教，应绑定具体选择和后果。
- 不允许所有变量同时上升的完美选项。
- 不允许只靠坏人、误会或突发事故制造冲突。
- 不允许前章设置的 flag 在后文完全没有体现。
- 不允许结局条件与实际玩家路径脱节。
- 不确定的信息可以合理假设，但必须在制作备注中标记。

## 人工编辑闭环建议

后续编辑闭环可以按以下步骤实现：

1. 生成初稿制作包。
2. 按质量评分标准自动生成审校报告。
3. 人工选择需要修改的章节、角色、选项、变量或结局。
4. 局部重写目标元素，并保留上下文约束。
5. 重新运行结构校验和可玩性校验。
6. 保存修订版本，并记录修改原因。

编辑闭环的最小可用版本应支持局部编辑，而不是每次重写全稿。

## 进入制作的最低门槛

一份剧本进入后续游戏制作前，至少满足：

- 总评分不低于 32/40。
- 没有低于 3 分的质量维度。
- 所有关键 NPC 都有明确诉求和转变条件。
- 所有关键选项都有变量变化、flag 变化或 NPC 状态变化。
- 每个结局至少有一条可解释路径。
- 前端可以从剧本中拆出章节、节点、选项、结果和复盘文案。
- 规则模块可以从剧本中消费初始状态、选项效果、flag 和结局条件。
