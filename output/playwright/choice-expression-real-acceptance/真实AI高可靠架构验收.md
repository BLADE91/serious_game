## 2. 核心实现

### 2.1 选择—表达协议

- 新增 `SelectionTask / SelectionResult / ExpressionTask / ExpressionResult`。
- 单选、多选只接受服务端候选 ID；归一化不会猜测或修正越权选项。
- 表达阶段只接收已经确认的选择和允许事实；业务状态只由选择 ID 与规则层产生。
- 表达增加短句、口语化、禁止舞台动作堆叠和禁止推断未提供职责等约束；角色会谈最多 360 字，夜间/群组表达最多 320 字。
- OpenAI 兼容适配器使用窄 JSON Schema，拒绝重定向，并以整个 HTTP 响应绝对截止时间约束调用。

### 2.2 配置能力门槛

- 个人 API 与服务器默认真实接口均通过六项能力测试后才允许进入活动存档：单选、多选、人物表达、夜间 follow-up、合同转写、行政文书转写。
- `GET /api/ai/config` 只返回脱敏 host、模型、能力状态、兼容状态和测试时间，不返回 Key。
- 配置失败保留旧配置；配置版本在请求开始冻结，线程池、流式响应和同一次夜间结算使用同一网关实例。
- 生产环境禁止 Fake；真实接口禁止 Fake fallback。

### 2.3 夜间 Agent 与强制会谈

- v3 剧本包定义 D10、D29、D40、D55、D70、D84 的条件、合法参与者、类型、议题、诉求和候选方案。
- 联系人、邀请、行动和 follow-up 均改为最小选择任务；对白单独生成。
- D10/D40/D55/D70/D84 在条件满足时强制创建会谈；D29 同时保留普通私下行动与赵建国倒戈/求保护会谈两条路径。
- 技术失败不会结算 `night_hold_position` 或生成泛化晨卡，而是使整个日终保持可重试且状态不变。
- 群组会谈最多三轮；完成前阻止普通行动。选择、表达、事实边界、attempt lease 与最终提交保持同一所有权链。

### 2.4 会谈、合同、文书与存档

- 人物会谈和班子会议先选择行为/立场，再生成自然发言；会议决议由确定性选择形成。
- 合同金额、住房、日期和资源由玩家与规则层形成不可变计划；AI只转写条款、选择签署意见和解释确定的问题 ID。
- 行政文书由引擎先形成文种、对象、责任、期限、资源与公开范围，再由 AI 分段转写；权威锚点校验禁止新增权限或承诺。
- manual save 在保存前校验 session 语义哈希与同版本自动快照；手动槽保存完整 payload。load 恢复完整业务状态，阅读游标仍只做前端“不后退”处理。
- Memory、SQLite、MySQL 均补齐手动快照完整 payload；MySQL 新增迁移 `0004_manual_snapshot_payload_mysql.sql`。
- 地图 DTO 显示真实地点名称，档案枚举在后端中文化；强制会谈复盘保留真实 `story_day`。
