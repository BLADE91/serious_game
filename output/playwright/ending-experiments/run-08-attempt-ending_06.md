# RUN-08：权威合同批量驱动首次尝试——实际 `ending_06`

## 实验编号 / 名称

RUN-08；公开 API 玩家客户端完整周目；合同批量驱动首次尝试。

## 实验目的

把袁桂兰两户探针扩展为多户合同流，验证批次、条款、审阅、签署与日结能否连续组合。

## 环境与版本

HEAD `dad11890cf820c662dad927d879e88b4cd9046ef`；test/memory/Fake/default `pkg_gameplay_v3`；session `sess_4062b7e92cda99555fdf1e5cd00be245`；公开 HTTP API 玩家客户端。

## 实验假设

若实验客户端能对每个异常都正式结束当前行动，后续代表户群可继续建立批次。

## 自变量（关键选择策略）

守程序、公开检测、医疗兜底、如实上报；首次批量应用人口房型与困难资源规则。

## 控制变量

全新局 D1–D90；合法公开请求；不改数据库、session state、快照或隐藏字段。

## 实验步骤

新建局→D2 会谈→自然推进并建立合同批次→逐户条款/审阅/签署→D90 结局。

## 原始观察（含关键日与夜间对话）

- 首批共记录 8 次合同尝试，仅 6 户签署。
- YUAN-02 错配非无障碍房后 409；实验客户端未在异常后结束基础行动，后续行动均被“已有一项基础行动正在进行”拒绝。
- 本局未触发玩家可见夜间对话（0 场）。

## 结局与 14 轴 / 旗标的玩家可见摘要

实际 `ending_06` / `ending_06d`；A 溃败，C 端掉，D 干净，T 揭而未治，M 温和，其余见原始结果。

## 预期对比

预期扩展至 30 户；实际 6 户。根因是实验客户端对低楼层规则及异常收尾处理不完整，不判产品缺陷。

## 玩家体验

409 中文原因明确；一次合同错误后仍需玩家显式结束当前行动，流程负担较重但状态行为一致。

## 缺陷记录

无产品 Blocker/High；属于实验路线失败。

## 内容质量观察

未发现新的连续重复、AI 腔、元话术或角色同声。

## 证据文件

`run-08-result.json`。

## 实验结论

未新增结局覆盖；促成实验客户端使用 finally 正式结束行动，并识别 low_floor 需要无障碍房。

## 可复现性

高；保留原始 409 与后续行动冲突响应。
