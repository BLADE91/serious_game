# RUN-10：权威合同达标基线——`ending_17`《独木难支》

## 实验编号 / 名称

RUN-10；公开 API 玩家客户端完整周目；33 户权威合同达标基线。

## 实验目的

验证玩家通过公开的会谈、逐户合同批次、条款填写、本人审阅和签署流程，自然达到 30 户目标线，并建立后续达标结局的可复用基线。

## 环境与版本

HEAD `dad11890cf820c662dad927d879e88b4cd9046ef`；test/memory/Fake/default `pkg_gameplay_v3`；全新 session `sess_e36210fb465dbefaf91fd13db42ec3bc`；公开 HTTP API 玩家客户端。

## 实验假设

若至少 30 户完成权威合同签署，A 轴应脱离“溃败”；其余 13 轴与旗标继续按剧情路线决定主结局优先级。

## 自变量（关键选择策略）

独立专班、守程序、公开检测、医疗兜底、如实上报、依礼处理宗族事务、公开村账、真实安置房、原账移交、环评公开与责任自省；逐户合同按政策最低现金、对应人口房型及公开困难资源填写；D75 后不再选择公示期内奖励。

## 控制变量

全新存档；D1–D90 逐日提交合法公开 action/end-day；公开 state version 与唯一 client ID；不直接修改数据库、session state、快照或隐藏字段。

## 实验步骤

公开创建新局→D2 完成吴秀英会谈→在人物机会自然解锁后建立代表户群合同批次→逐户填写条款、审阅、本人签署→每日正常结束→D90 读取结局、review 与治理台账。

## 原始观察（含关键日与夜间对话）

- D53–D84 共处理 34 份合同，33 份签署成功，0 个请求错误；谭老六户群因路线前置未形成批次。
- D75 前合同使用公示期内奖励；D77、D78、D84 合同关闭该奖励，均正常签署。
- D90 权威签约 33/36，A=宽裕，命中 `ending_17` / `ending_17b`。
- 共 13 场玩家发起的治理会谈；**本局未触发玩家可见夜间 Agent、强制群组或夜间 follow-up（0 场）**。

## 结局与 14 轴 / 旗标的玩家可见摘要

- 主结局 `ending_17`《独木难支》；亚结局 `ending_17b`《结盟发稿》。
- A 宽裕；C 端掉；D 干净；T 揭而未治；M 温和；X 实；R 据实以告；P 疏离；F 揽责；Z 中立；J 立案；K 结怨；E 结盟发稿；V 背书。

## 预期对比

预期 A 达标且进入晚期结局家族；实际 33 户使 A=宽裕，按表序先命中 K=结怨的 `ending_17`，与规则一致。该结果也证明 `ending_18`–`ending_23` 会被更高优先级的 K 条件遮蔽，后续需改变宗族路线。

## 玩家体验

合同流能清楚体现“会谈不等于签约、审阅不等于本人签署”，但 36 户逐份填写的操作成本很高。资源不足会返回明确中文原因；达标后结局对“项目办成、班子关系失衡”的回放与本局选择一致。
