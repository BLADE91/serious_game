# RUN-30：headed UI 公开治理代表局——`ending_21`《揭而未治》

## 实验编号 / 名称

RUN-30；真实 headed Chromium 代表性复走；公开污染但未形成治理闭环。

## 实验目的

在真实浏览器中验证 ending_21 路线的建局、D90 结局入口、主/亚结局、14 轴、全文和附记呈现，并检查 1920×1080 几何与 console。

## 环境与版本

backend `aa58140870367c2969ea53f0941e0d728e0c2714`，test/memory/Fake/default `pkg_gameplay_v3`；前端结局卡初测 aa5814、修复复测 `55e4fa20321da6b93da2cb6137cccadef94d39cd`；session `sess_81934665d17b9cc73072597b653bf178`；headed Chromium 1920×1080。

## 实验假设

公开环评/血铅、保持干净温和、封存旧账且班子拥护，应命中 ending_21；修复前后 UI 对同一 memory session 的呈现应可直接比较。

## 自变量（关键选择策略）

D60 避免先行立案；D75 选择患儿复检治疗；D81 封存铁盒；D82 全部见报；D83 把名册交记者；D85 班子拥护。

## 控制变量

浏览器登录并从“开始新游戏”创建全新局；同一 session 其余逐日推进由获准的合法公开玩家 API 完成，不改数据库、快照、隐藏字段或 repo；33 户全部走公开合同条款/复核/签署。

## 实验步骤

1. 在 1920×1080 headed Chromium 由玩家入口创建全新 D1 存档。
2. 用合法公开请求将同一 session 从 D1 逐日推进至 D90；浏览器保存并载入该局。
3. 浏览器检查 D90 督办、33/36 台账、复盘时间线中的 D46/D57/D75/D82/D85 选择。
4. 点击“查看结局复盘”，检查结局卡、长文、14 轴、亚结局和三条案卷附记。
5. 记录 scrollWidth、viewport 和 console。

## 原始观察（含关键日与夜间对话）

- D90：33/36，实际 `ending_21` / `ending_21a`，0 请求错误。
- 复盘时间线可见 D57“深夜的敲门声”（选择“听着，不表态，把话留在屋里”）、D58“围堰漫了”（连夜抢险并上报）、D75“夜里那通电话”（不见面，让对方在电话里说完后挂断）。这些是脚本事件/决定，没有 Agent 发言轮次或强制群组逐句对白。
- 本局未触发玩家可见夜间 Agent、强制群组或夜间 follow-up 对话（0 场），故无参与者轮次可逐字转录。
- 1920：`scrollWidth=1920`，无横向溢出；console 0 error、0 warning。

主结局“揭而未治”，余波“背书”；A宽裕、C未触碰、D干净、T揭而未治、M温和、X实、R据实以告、P疏离、F揽责、Z中立、J未起疑、K拥护、E结盟发稿、V背书。三条附记分别说明血铅名册、铁盒和绳子的去向。

路线与 ending_21 规则一致。aa5814 初测点击复盘后数据请求 200 但 UI 不显示结局卡；前端 55e4fa 复测后，main/sub、14轴、全文、附记均正常显示。
